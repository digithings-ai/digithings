The same modules make different applications. A use case is a choice of
modules, not a separate product, and each of them starts on a single machine.

## Financial research

A research desk needs market data, a way to test ideas against history, and
results it can defend. Most tooling for this is either a spreadsheet that
cannot be audited or a closed platform whose methodology you take on trust.

digiquant gives the work an ordered pipeline: data, strategy validation, backtest, optimisation and export, each stage reading only what the stage before it
wrote. digigraph routes questions to it, digisearch brings in the filings and
notes around a position, and digichat is where the analyst asks and reads.
Every result carries its provenance, so an analyst can defend a number to
someone who doubts it.

On one machine this is a private research environment for a single analyst.
For a team, the pipeline moves to a shared server, backtests run on a timetable, and identity decides who can see which research.

## Voice

Speech is the input people are least willing to share, and the usual way to
process it is to stream it to someone else's servers. digivoice starts from
the opposite default: capture, transcription with whisper, an optional rewrite
by a small local model, and speech back with Piper, all on the speaker's own
Mac. There is no cloud option, on purpose: the audio never leaves the machine.

Because the output is ordinary text, voice becomes a way into the rest of the
stack. A finished transcript pastes into whatever is in focus: a question in the
chat, a research brief, made out loud while the hands are busy. digichat can
also switch on the browser's own dictation and read-aloud, which is convenient
but uses whatever speech engine the browser ships.

## Retrieval over your own documents

Most of what a team needs answered sits in its own files: contracts, notes,
past research. Retrieval brings it to the model:
your documents are split into passages, indexed by meaning, and the passages
that matter are handed to the model with the question. The answer cites what
it stands on, so a reader can check it.

digisearch owns the two halves, ingestion and answering, and keeps them
apart. digivault holds documents as linked markdown, and digillm connects
whichever model you choose. A workspace filter can travel with each query, so one index can hold
several teams' documents. The same pipeline runs against a
folder on a laptop and against a department's archive on managed storage.

## Agents and exploration

An agent is a model that is allowed to act. It is given tools, such as search
this index or open a ticket, and it picks one, reads the result and picks
again until the task is done. It needs the tools, the loop, a way to ask a
person before anything risky, and a record. digigraph runs the loop, MCP
carries the tools, a gate per tool server decides what may run unattended, and
digitrace keeps the trail.

The first agent is usually a handful of scripts a team already has, each
given a name, an input schema and a description and served from a small MCP
server. Claude Desktop or a code editor can connect to the same server, so the
tools a team writes once work in the stack and outside it. Exploring a new idea
means adding a tool, not building a new agent framework around it.

## At a glance

| Use case | Modules it runs | Starts on | Grows into |
| --- | --- | --- | --- |
| Financial research | digiquant, digigraph, digisearch, digichat | One analyst's machine | A shared research server with scheduled runs and access by role |
| Voice | digivoice, digichat | The Mac with the microphone | Any app on that machine: the transcript pastes wherever the cursor is |
| Retrieval | digisearch, digivault, digillm, digichat | A folder on a laptop | A department's archive on managed storage, with access rules per query |
| Agents | digigraph, digitrace, your MCP servers | Your own scripts as MCP tools | Many tool servers under one approval gate, shared with outside agents |

## One question, four modules

The use cases are not separate lanes. An analyst dictates a question about a
holding, and digivoice turns it into text without the audio leaving the
machine. In the chat, the hub asks the verticals what they offer: digisearch
returns the filing passages behind the position, and digiquant reruns the
backtest under the stated parameters. The answer cites both, and with tracing
on, the trail shows every step that produced it.

No code was written for that question. Each module did its one job, and the
application is the set of parts that were switched on. The same chain runs
unchanged when the research moves to a shared server, and that is how an idea
proved on one machine grows without starting again.
