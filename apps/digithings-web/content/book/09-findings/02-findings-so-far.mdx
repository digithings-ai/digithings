The architecture chapter produced the first five findings. The deployment
reference described the chat scaffold as removed and its plan as free, while
the running chat worker serves live traffic. No automated lane ships two of
the production stacks; both ship outside the pipeline. The provider guide
claimed a weekly routine the scheduler no longer keeps. The vision material
calls the model library a future migration, while the hub already relies on
it across many modules. And the vision material says the chat is not public,
while the live chat serves the main site. Two further candidates were
withdrawn after re-measurement against the current tree.

The foundations review, done while collapsing the early chapter tickets into
this batch, checked the architecture chapter claim by claim against the
running tree. The module map, runtime tool discovery, identity checks on
every hop, the routing layer image, static hosting, the archive store, the
vault format, the chat running with no database in production, and the
self-hosted tracing all hold. No new mismatch was filed.

The review settled two things directly. The chapter order had two chapters
sharing one position, so the spine now reads from motive to mechanism: why a
book, why self-hosted, how the system fits together, how it scales, and what
it costs. And the chapter maps the request path — hub, verticals, identity,
models, data, chat — while the voice interface, the skill compiler and the
developer tooling stay out of scope until they join that path. That scope is
a decision, recorded here, not an oversight to re-file.
