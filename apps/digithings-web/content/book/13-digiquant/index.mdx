digiquant is one example of what a domain service looks like: one
discipline's rules, packaged so the rest of the stack can call them. Here the
discipline is quantitative research, and its failure mode is unusual. Results
look rigorous and are not: a backtest that peeks at the future, steps run in a
convenient order, a number nobody can reproduce. Each one manufactures
confidence. digiquant makes those outcomes hard to produce by accident,
because the honest order of operations is the only order the pipeline will run.

A digiquant number is only as good as the process behind it, so the process
is fixed. Research follows one path. Each stage declares what it reads, and
every result records the engine and build behind it, so it can be checked
later.

## How it works

The unit of work is the whole pipeline. A caller asks for a research task;
digiquant runs the stages in order on NautilusTrader, an open trading engine
pinned so any result can be reproduced, and returns the result with its
provenance attached.

```mermaid each arrow is a contract: a stage reads only what the stage before it wrote
flowchart LR
  DATA[data] --> VAL[validate]
  VAL --> BACK[backtest]
  BACK --> OPT[optimise]
  OPT --> EXP[export]
```

The engine replays history one bar at a time, so a strategy cannot read a
price before its moment; that is what keeps look-ahead bias out. The fixed
order keeps the rest out: nothing is optimised before it has been validated
and backtested. A result whose engine cannot be identified comes back marked
partial and not citable, with no plausible number to mislead anyone. The
cost is one engine. A strategy written for another has to be ported.

## Where it fits

digiquant publishes its tasks as tools, to the hub and over MCP, so a caller
can ask for research without knowing how quant work is ordered. Results go out
to whoever asked, whether that is the chat, a scheduled session or a
dashboard. The stack has one rule here: no other service may state a Sharpe
ratio, a profit or a trade count unless it came from digiquant. Each result
names the engine version, the pin and the lockfile it ran on, so a number on a
dashboard leads back to the build behind it.

The pipeline runs wherever compute is cheapest: beside the data for fast
backtests, on a timetable in the cloud, or on hardware sized to the workload.
The ordering rules travel with it, because they are written into the code.
