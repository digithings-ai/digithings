summary: >-
  Every module with tools publishes them over the Model Context Protocol, so
  any MCP client can use digithings and digithings can use any MCP server.
---

The Model Context Protocol (MCP) is an open standard for describing tools that
an AI agent can call. digithings is built **MCP-first**: digigraph, digisearch,
digiquant and digivault each run an MCP server, and the hub is an MCP client
for any tool server an operator adds. MCP is a layer on those modules, not a
module of its own. Inside the stack, the verticals reach the hub over a plainer
HTTP manifest, because the hub handles their results specially.

That has consequences in both directions. Outward, an agent you already use,
whether a desktop assistant, an IDE agent or your own code, can connect to
digithings over MCP and use its search, research and memory tools directly.
Inward, digithings can use any tool server that speaks MCP, so extending it
rarely means writing digithings-specific glue.

Direct tool access is powerful, so it is guarded separately. Reaching the tool
servers from outside requires its own credential, distinct from the identity a
chat user holds, and the edge refuses requests when that credential is missing.
The hub's own tool permissions cannot be bypassed by going around it.

> **Why digithings.** Standard protocols at every boundary: MCP for tools, the
> chat-completions interface for models, signed tokens with published keys for
> identity and OpenTelemetry for telemetry. Each boundary is a place you can
> plug in something else.
