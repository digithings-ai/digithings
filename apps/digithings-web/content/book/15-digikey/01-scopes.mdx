---
title: Scopes, the narrow grant
order: 1
summary: >-
  How each credential carries exactly what it allows, and why narrow grants
  keep incidents small.
---

A credential that can do everything is a catastrophe waiting for a leak.
Scopes are how the system avoids minting one. Every credential carries a
short list of named permissions, each a service and an action such as
`digiquant:backtest` or `digivault:read`, and every service checks the list
before acting. A credential with `digivault:read` cannot write a note, not
because operators are careful, but because the grant never included
`digivault:write`.

Scope design follows two habits. Grants start narrow and widen on request,
never the reverse; it is easy to add a permission someone needs and nearly
impossible to notice one nobody needed. And scopes name actions a person
recognises, chat, run a backtest, search, add documents, rather than routes,
so an operator can reason about a grant without reading code.
