Most people never meet the stack. They meet digichat, the chat surface where
questions go in and answers stream out. Everything behind it, the hub, the
verticals and the models, serves that surface, and the
surface itself does very little.

A person signs in, opens a conversation and talks. Answers stream in as they
are produced, history is kept per conversation, and artifacts such as
documents and visuals render beside the chat rather than inside a wall of
text. The same interface can be embedded in another site, so a host can offer
the experience to its own visitors with the same backend behind it.

Dictation and read-aloud are two more ways into the same conversation: the
browser's own speech support, off by default, not a digithings model. Chrome
sends that audio to Google, so keep dictation off for anything confidential.

## How it works

digichat is two parts that travel together: a request layer and a surface.
The request layer signs the person in through any OpenID Connect provider,
swaps that session for a short-lived digikey token and forwards the message
to the hub with it. The
surface renders the streaming answer, the history and the artifacts.

Neither half holds anything worth stealing. Sessions are verified on every
request. Conversations live in the browser, and in Postgres when one is
configured, never in the server.
Embedded visitors are authorised per host before they see anything, and a
registered host alone authorises nothing: the credential for that visit
does.

## Where it fits

digichat relies on digikey for identity and on the hub for answers. The hub
is its default backend, not its only one: one setting points it at an
OpenAI-compatible endpoint, Anthropic, Google Vertex or Azure AI Foundry
instead, which is useful for a plain chat with no tools behind it.

It works the other way too. The hub speaks the standard chat format, so any
client that speaks that format and carries a valid token can sit where
digichat sits.

## Where it runs

On a laptop it runs beside the stack it talks to, so development stays a
single checkout. In the cloud it is a container in front of the hub and
verticals; on your own servers, wherever you already serve web traffic.

In every home it stays stateless. Stop it, move it or run ten copies, and
conversations survive, because the server never held them.
