---
title: "Two kinds of scale"
order: 1
summary: >-
  Load and capability are different problems. One is solved with copies and
  hardware, the other with modules, and each module is honest about which it
  can do today.
---

"Scale" means two different things, and mixing them up is how a reasonable
design turns into an expensive one.

**Load** is more requests, more data, more people at once. Whether a module can
take it by running more copies depends on where it keeps its state. digichat
keeps conversations in the browser and, when configured, in Postgres, so any
number of copies can serve the same users. The hub can keep its conversation
threads in Postgres too, but its rate limits and the tool calls waiting for a
person's approval live in its own memory. Two copies of the hub would each see
half of them, so for now the hub scales up, on a bigger machine, before it
scales out.

**Capability** is the application learning to do more: retrieval, then a
research pipeline, then tools that act on other systems. That is solved by
switching on a module, not by making an existing one bigger.

The two need separate answers, and a stack that says plainly which modules can
run as many copies, and which cannot yet, is easier to plan for than one that
claims they all can.
