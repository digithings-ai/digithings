digithings started as one builder's own AI stack: the parts needed to use AI
for real work, on a laptop or in the cloud, without a vendor deciding which
model, which database or which interface that work has to use. It is published
whole, under the MIT licence.

AI tooling changes every few months. A better model, a cheaper vector store or
a new agent client arrives, and most applications need a rewrite to take it.
This stack is shaped so they need a setting. The book explains the shape and
the decisions behind it; setup and endpoints live in the documentation.

## What we hold to

**Own the stack.** Every part is code you can read, run and change. When an
answer looks wrong, you can follow it to the line that made the decision.

**Location is a deployment decision.** The same services run in Docker on a
laptop and in containers in a cloud account, and read the same setting names in
both. Moving them changes values, not code.

**Open at the seams.** Models are reached over the OpenAI chat format, tools
over MCP, identity as standard signed tokens and traces over OpenTelemetry.
Each is a standard the stack did not invent, so any part can be swapped for
something else that speaks it.

**Small parts, one job each.** Model access, orchestration, retrieval,
identity, tracing and the interface are separate modules. A project that only
needs search over its documents runs retrieval and leaves the rest off.

**Grow in place.** A solo builder and an organisation use the same contracts.
Capability and cost go up as the work proves itself.

**Show the working.** Answers cite the passages they used, backtests record
the engine build that produced them, and with tracing on, every request leaves
a trail. Trust comes from what the system records, not from what it claims.

## How to read it

The case comes first: software that can live anywhere, an open core, a stack
that scales without a rewrite, and what people build with it. Then the modules,
each with what it does, where its seam is and what it costs to replace. It ends
on your own machine, with the first thing to build.

Read it through in one sitting, or open the chapter your question lives in.
