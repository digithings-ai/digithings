The laptop is usually treated as a developer convenience, a
smaller and vaguer copy of the real system. That is backwards. If an
application cannot run on your own computer, it is hard to trust, hard to
debug and hard to hand to anyone else. So the first deployment of anything
built on digithings is the computer in front of you.

## The first hour

Choose the model first: a hosted provider's key, or the one setting that
keeps every call on the machine with Ollama. That choice decides where your
passages go, so make it before you load anything of your own. Then start the
local stack with the chat and trace profiles, load the sample documents with
one command and ask the chat a question about them. The first thing you see is
the whole loop working: the interface, the hub, retrieval, a model and a trace
of what happened.

## The first week

Pick the one use case closest to your work and switch on only what it needs.
For research, that is the research vertical and retrieval over your own
notes. For documents, retrieval and the vault. For an agent, the tools you
already have, described over MCP so the hub can call them. Keep the trace on
and read it. It shows how the system reached each answer, which is the
fastest way to learn where to change it.

## When it outgrows the machine

You will know, because the trace and the machine both tell you: a pipeline
that needs more memory, an index that has grown past the disk, more people
than one machine should serve. At that point, move the module that is under pressure, not the
whole stack. Put it on a server you own or in a cloud account, point its neighbours at
the new address (one setting per neighbour) and carry on. Its tools,
its settings and its credentials work there unchanged.

## Where to go next

The design decisions behind each module, with references into the code, are at
digithings.ai/book. The code is open under the MIT licence, and every module
carries its own architecture notes.

If you would rather have it fitted than fit it yourself, the people who
maintain digithings do that work: connecting it to your documents, your
sign-in and the systems you already run, or running it for you under a
contract, with a way to take the deployment with you. Write to
contact@digithings.ai.
