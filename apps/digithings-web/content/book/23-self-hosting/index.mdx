title: Start on your machine

summary: >-
  The first deployment is the computer in front of you. Prove the application there, then move it to a cloud account when it needs more.
---

Most infrastructure projects treat a laptop as a developer convenience: a
smaller, vaguer version of the real system. That is backwards. If an
application cannot run on your own computer, it is hard to trust, hard to
debug and hard to hand to anyone else.

digithings runs fully on one machine: the hub, the modules, the chat surface,
the data and the tracing. You can prove the application end to end before you
pay for a server. The same contracts, setting names and service layout apply
when it moves.

The point is not local for its own sake. The point is that location becomes a
deployment decision. Stay on your machine while the work is small. Move to a
cloud account when it needs more capacity. Split a module onto another machine
when one part grows faster than the rest. The application does not become a
different application.

That freedom depends on open source, open protocols and a stack that does not
hide its seams. A module you cannot inspect is a module you cannot move.

> **Why digithings.** Build it on a Mac, prove it, then place it where it
> belongs. The stack is designed for that move, not for a single vendor's
> data centre.
