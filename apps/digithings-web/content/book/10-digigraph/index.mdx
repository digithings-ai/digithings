When a request arrives, something has to decide what happens next. A chat
message, a research job and a dashboard widget all need the same loop:
understand the request, pick the tools, run them in order and return the
result. Without a hub, every caller writes that loop again and the copies
drift apart. digigraph owns it once, so every interface shares one routing
behaviour, one tool contract and one streaming format.

The hub is kept deliberately small. It routes, dispatches and streams,
and leaves the real work to the verticals that own it.

## How it works

digigraph runs each request through a state machine with stages for
research, validation, backtesting and optional optimisation. Conditional edges
decide which stages a given request needs. Around the machine sits a
registry of tools. A few live inside the hub; the rest belong to the
verticals, which publish descriptions of what they offer. The hub fetches
those descriptions at runtime and never carries a hard-coded list.

```mermaid the hub asks each vertical what it offers instead of assuming it
flowchart LR
  IN[request] --> HUB[state machine]
  HUB --> ASK[ask for tools]
  ASK --> RUN[run tools]
  RUN --> OUT[streamed answer]
```

Because the hub asks, nothing has to be registered in advance. A vertical can ship a new
tool without a new release of the hub, and a tool server the operator adds works as soon as it describes itself. A question about a company's
filings, for example, reaches retrieval because retrieval said it can search
documents, not because the hub was told where documents live.

## Where it fits

The interfaces send the hub chat-shaped requests, and it answers in the
streaming format ordinary chat clients already understand. Downstream it
calls the verticals for retrieval and research, and models through the shared
model layer. Identity arrives as a short-lived signed credential that the hub
verifies itself rather than trusting the caller. With tracing on, every step is recorded, so a routing
choice can be questioned after the fact.

The hub holds no list of where its neighbours live, so moving a vertical to
another machine changes the hub's configuration and nothing else.
