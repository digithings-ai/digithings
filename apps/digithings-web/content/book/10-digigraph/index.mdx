When a request arrives, something has to decide what happens next. A chat
message, a research job and a dashboard widget all need the same loop:
understand the request, pick the tools, run them in order and return the
result. Without a hub, every caller writes that loop again and the copies
drift apart. digigraph owns it once, so every interface shares one routing
behaviour, one tool contract and one streaming format.

The hub is kept deliberately small. It routes, dispatches and streams, and
leaves the real work to the verticals that own it. A hub adds one more hop on
every request, and one place where a routing mistake affects every caller.

## How it works

digigraph runs each request through a state machine built on LangGraph. The
first stage runs the tools the request needs. Later stages are optional and
vary by use case. A question about documents ends after the first, while a
trading strategy goes on through validation, backtesting and optional
optimisation. Around the machine sits a registry of tools. A few live inside
the hub. The verticals own the rest and publish their descriptions, the name,
the inputs and what the tool does, which the hub fetches when it first needs
them.

```mermaid the hub asks each vertical what it offers instead of assuming it
flowchart LR
  IN[request] --> HUB[state machine]
  HUB --> ASK[ask for tools]
  ASK --> RUN[run tools]
  RUN --> OUT[streamed answer]
```

Each service writes its own tool descriptions, so it can improve them without
a hub release. A question about a company's filings reaches retrieval because
retrieval described a document search, not because the hub was told where
documents live.

## Where it fits

The hub speaks the OpenAI chat format, so digichat, Open WebUI or a short
script can call it and read the streamed answer. Downstream it
calls the verticals for retrieval and research, and models through the shared
model layer. Identity arrives as a short-lived signed credential that the hub
verifies itself rather than trusting the caller. With tracing on, every step is recorded, so a routing
choice can be questioned after the fact.

No address is written into the hub's code, so moving a vertical to another
machine changes one line of its configuration.
