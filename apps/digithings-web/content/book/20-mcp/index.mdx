A system with dozens of capabilities needs one way to say what each of them
does, readable by people and by models alike. The Model Context Protocol is
that way: each tool has a name, a schema for its inputs and a description,
offered over a standard transport. digithings uses it everywhere. Every
capability the system offers is a described tool, and every tool a model can call passes the same allow-list.

The payoff is how new things plug in. A new search source, a new analysis or
an integration with a team's tracker arrives as a tool description, and every
part of the system already knows how to read one. Nobody patches the hub, the
chat or the dashboard to adopt it. Once the description exists, the tool is integrated.

## How it works

Tools live behind servers that advertise them. The hub lists what each
server offers, filters the list through the operator's allow-list, and shows
the model only what survives. A tool call carries the caller's identity, so
it is authorised with the same scopes as any other request. A gate per
server decides which tools may run unattended and which need a person to say
yes first.

```mermaid offered and executed are checked separately: a model only sees tools it may call
flowchart LR
  SRV[tool server] --> LIST[allow-list]
  LIST --> GATE{may it run?}
  GATE -->|yes| RUN[runs]
  GATE -->|ask| PERSON[a person approves]
  PERSON --> RUN
```

The gate is checked where the tool executes, not only where it is offered.
A model is never shown a tool it could not call, and a call never relies on
the offer alone. So a prompt that talks a model into trying a forbidden tool still fails at
the gate.

## Where it fits

The protocol is how tools reach the hub from outside it. Operator tool
servers publish through it, and outside agents and code editors connect to
the system's own tool servers through it. The verticals describe their tools
to the hub in the same shape. Because the
protocol does not care about transport, the contract is the same on one
machine and across a network; only the list of connected servers changes.
