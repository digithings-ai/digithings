Before the system runs anywhere else, it runs here: one machine, every
service beside its neighbours, the full loop from question to answer on
hardware you can touch. The local stack is not a demo mode or a trial with
features removed. It is the same system arranged for one machine.

You need Docker and about 20 GB of free disk; a local model also wants
plenty of memory. Services start side by side, talk over the machine's own
network and keep their data in local stores. A developer runs the same
composition they ship, and a small firm can run the whole product on one
well-chosen computer. There is no digithings account. Model calls go wherever you point them: a
provider with your own key, or Ollama on the machine, one setting apart. Which
one you choose decides where your text goes.

## How it works

One Docker Compose file describes which services run, what each needs and
how they reach each other. `make up` starts the core: identity, the hub,
research, retrieval, tracing status, the model router and Ollama. The chat,
the vault, the MCP servers and a trace collector are profiles you add.
Stopping it puts everything away. Sample documents ship with it and load with
one command.

```mermaid one file describes the whole machine; the services inside are the ones that run everywhere
flowchart LR
  FILE[one composition] --> HUB[hub]
  FILE --> VERT[verticals]
  FILE --> MODELS[local models]
  FILE --> STORES[local stores]
```

The services behave exactly as they do in any other home, and a request is
signed and checked exactly as in a cloud account, because the code never
learns where it is running. The only local concessions are friendlier defaults and warm
caches.

## Where it fits

The local stack is where the working day happens: development, experiments,
demonstrations and small production workloads. digithings runs its own
production on the cloud home instead; nothing in the stack insists that a
client do the same. The last chapter covers what happens when one machine is
no longer enough.
Nothing written against the local stack has to be rewritten, so work done
locally carries straight over.
