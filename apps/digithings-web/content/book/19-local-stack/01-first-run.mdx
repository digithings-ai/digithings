title: The first run

summary: >-
  From checkout to a working stack, and what to look at when something does
  not start.
---

The first run should feel uneventful. Fetch the checkout, run `make up`, and
watch each service report healthy in turn. Then load the sample documents
with `make seed-digisearch-local`, using a key allowed to add documents, so
retrieval has something to find. Most of the first run's time goes on
downloading images and model files; after that, starting is quick.

When something does not start, the order of inspection is fixed. First the
composition's own status: which service is unhealthy, and what did it log
last? Then dependencies: did storage and the model runner come up before
the services that need them? Then resources: is there memory and disk to
spare? Most first runs end at one of those three steps. A failure that is none of
them is worth reporting, because it improves the composition for everyone
after.
