# copy that next itself pulls is now the patched one: at next@16.4.0 the
# top-level `node_modules/sharp` resolves to 0.35.5, which is `>=0.35.5`, so next
# is no longer the reason this advisory is open. The single copy still in range is
# `node_modules/miniflare/node_modules/sharp` at 0.35.4 (audit `range: "<0.35.5"`,
# `effects: ["miniflare"]`).
#
# Reachability: dev-only. That copy belongs to wrangler/miniflare (workerd local
# dev). Nothing under apps/, packages/, scripts/ or tools/ imports sharp, no worker

# sharp's only entry point on a deployed surface — never runs.

# dangerouslyAllowSVG, adds a cf:image binding, or imports sharp directly.

# ── Accepted risk: braces 3.0.3 — no patched release exists ─────────────────
#
# Both remediations SECURITY.md prefers come before an ignore entry, and both
# are closed here. The advisory covers braces <=3.0.3 and 3.0.3 is the newest
# release npm has (`npm view braces version` -> 3.0.3, lockfile pin 3.0.3), so
# there is no patched version to pin and no other version to swap to. npm's own
# `fixAvailable` — "replace shadcn with 1.0.0", isSemVerMajor — is not a
# remediation: it names a package unrelated to the vulnerable code and would be
# a major downgrade.
#
# Reachability: braces is reached only as micromatch <- fast-glob, and fast-glob
# only from tooling — eslint-config-next (a devDependency in all five workspaces
# that declare it) and shadcn, the code-generation CLI that apps/digichat
# declares under `dependencies`, which is why npm reports the chain as non-dev.
# Nothing under apps/, packages/, scripts/ or tools/ imports braces, micromatch,
# fast-glob, ts-morph, @ts-morph/common or shadcn, so no application code path
# loads the glob engine.
#
# The advisory is a stack-exhaustion DoS that needs a deeply nested *pattern*.
# Every pattern expanded through this copy is a literal in a committed config or
# in a build tool's own source; none is assembled from request data. Exploiting
# it would therefore require control of a glob string, which in this repo means
# repo write access — a larger problem than the advisory.
#
# Matched per advisory, not per package (SECURITY.md "Scope note"), so a future
# advisory against braces still blocks. Re-check when braces 3.0.4+ ships: bump
# the pin and delete this block rather than extending the comment.
GHSA-vfj7-8cjw-p6xm
