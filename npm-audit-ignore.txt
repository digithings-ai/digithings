# can do that: zero `sharp` imports under apps/, packages/, scripts/ or tools/;

# next@16.2.4 — HIGH, 2026-10-07 wave. Five advisories published together on
# 2026-10-07, all ranged `>=16.0.0 <16.3.8` with no patched release. Four are
# moderate/low and are therefore warn-only under SECURITY.md
# "Dependency-audit policy" ("Warn-only: MODERATE, LOW and unknown") — they are
# named here for the record and deliberately NOT listed as ids below, because
# accepting a low-severity advisory is not an acceptance Security makes:
#   - GHSA-4jqv-mc3x-m676 (medium, 5.3) SSG/ISR cache poisoning, Pages Router
#     only. Unreachable: no `pages/` directory exists anywhere in the repo.
#   - GHSA-39w2-rjm5-chcv (low, 5.4) `next dev` MCP endpoint disclosure. Dev
#     server only; never reachable from a built artifact.
#   - GHSA-f87g-xv8r-7p7x (medium, 5.3) App Router metadata image routes ignore
#     `dynamicParams` under webpack. Unreachable: zero `opengraph-image`,
#     `twitter-image`, `ImageResponse` or `next/og` in apps/* + packages/*.
#   - GHSA-mcj8-r9mp-w47p (medium, 4.8) SSG/ISR cache poisoning via root
#     catch-all. Unreachable: same Pages-Router precondition as above.
# All four clear with #4396 and need no entry.
#
# GHSA-cjq9-62q9-8jv4 (CVE-2026-94483, HIGH 6.5) is SSRF in Image Optimization
# and is the sole blocker in this wave. The advisory states the trigger is an
# "attacker-controlled, allow-listed remote URL", and its own workaround section
# says "If no `images.remotePatterns` are configured, your app is not affected."
# Three independent repo facts confirm that precondition holds at this commit:
#   1. `git grep -i remotePatterns` over apps/* + packages/* returns zero hits,
#      so there is no allow-list an attacker could be matched against.
#   2. Four of the five first-party Next apps — dashboard, digiquant-web,
#      digithings-web, reference — set `output: 'export'`. A static export emits
#      no `/_next/image` server route, so the optimizer does not exist at
#      runtime for them. All four also set `images: { unoptimized: true }`.
#   3. The only self-hosted Next server is apps/digichat (`output: 'standalone'`),
#      and it has zero `next/image` / `<Image>` imports in its own source, so no
#      code path can hand a remote URL to the optimizer. There are zero
#      `_next/image` references repo-wide. The `next/image` hits under
#      apps/digichat/reference/ are vendored assistant-ui templates that the root
#      `workspaces` globs (apps/*, packages/*) do not match, so they are never
#      built or deployed.
#
# Accepted rather than remediated for now, because the pinned 16.2.4 is the only
# version that keeps three Next builds green and #4396 is the tracked fix. Per
# SECURITY.md the earlier remediations were evaluated first: pinning a patched
# next is not possible below 16.3.8, and there is no second package to swap.
#
# Re-evaluate (any one of these removes this entry):
#   - #4396 lands at next >=16.3.8 -> delete this block and let the lane enforce.
#   - 2026-11-07, as a hard calendar backstop if #4396 has not moved by then.
#   - Any app adds `images.remotePatterns`, `images.loader`, `images.domains` or
#     `images.dangerouslyAllowSVG`, or any app leaves `output: 'export'` while
#     keeping the image optimizer, or any `next/image` import lands in
#     apps/digichat source. That makes the advisory reachable and it must block
#     again immediately — bump the pin instead of extending this comment.
GHSA-cjq9-62q9-8jv4

# ── Accepted risk: braces 3.0.3 — no patched release exists ─────────────────
#
# Both remediations SECURITY.md prefers come before an ignore entry, and both
# are closed here. The advisory covers braces <=3.0.3 and 3.0.3 is the newest
# release npm has (`npm view braces version` -> 3.0.3, lockfile pin 3.0.3), so
# there is no patched version to pin and no other version to swap to. npm's own
# `fixAvailable` — "replace shadcn with 1.0.0", isSemVerMajor — is not a
# remediation: it names a package unrelated to the vulnerable code and would be
# a major downgrade.
#
# Reachability: braces is reached only as micromatch <- fast-glob, and fast-glob
# only from tooling — eslint-config-next (a devDependency in all five workspaces
# that declare it) and shadcn, the code-generation CLI that apps/digichat
# declares under `dependencies`, which is why npm reports the chain as non-dev.
# Nothing under apps/, packages/, scripts/ or tools/ imports braces, micromatch,
# fast-glob, ts-morph, @ts-morph/common or shadcn, so no application code path
# loads the glob engine.
#
# The advisory is a stack-exhaustion DoS that needs a deeply nested *pattern*.
# Every pattern expanded through this copy is a literal in a committed config or
# in a build tool's own source; none is assembled from request data. Exploiting
# it would therefore require control of a glob string, which in this repo means
# repo write access — a larger problem than the advisory.
#
# Matched per advisory, not per package (SECURITY.md "Scope note"), so a future
# advisory against braces still blocks. Re-check when braces 3.0.4+ ships: bump
# the pin and delete this block rather than extending the comment.
