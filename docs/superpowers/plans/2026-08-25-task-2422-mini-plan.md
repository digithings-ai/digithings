# Mini-plan: #2422 Label legacy reconstruction (Task 2.5)

**Branch:** `task/2422-label-legacy-reconstruction-and-maintain` → `module/digiquant`  
**Goal:** Make source quality explicit so legacy `position_events` / prose projections cannot be mistaken for authoritative ledger fills/holdings.

## Design (additive)

1. **Migration `071_olympus_position_events_book_source.sql`**
   - Add `book_source text NOT NULL DEFAULT 'legacy'` to `position_events` with `CHECK (book_source IN ('legacy', 'authoritative'))`.
   - Existing rows stay `legacy` permanently (column default; no content rewrite).
   - Create curated views (service_role / authenticated as appropriate — **no** SELECT on private `portfolio_ledger_*` for anon):
     - `olympus_position_events` — all rows + `book_source` (compat mirror; existing readers may keep using base table).
     - `olympus_position_events_authoritative` — `WHERE book_source = 'authoritative'` only.
   - Ambiguous / unlabeled never appear in the authoritative view.

2. **Writer contract (`execute_at_open.py`)**
   - Ledger projection path upserts `book_source='authoritative'`.
   - Prose / reconstruction paths upsert `book_source='legacy'` (or omit → default).
   - Do not delete prose builders yet (cutover still `--no-ledger`).

3. **Tests**
   - Migration/contract tests: default legacy; authoritative filter excludes legacy; no public grant on ledger tables.
   - execute_at_open / projection tests: ledger path stamps authoritative; prose stamps legacy.

4. **Docs**
   - `SCHEMA.md` + `ARCHITECTURE.md`: labeling, cutover/retirement condition (retire legacy writers only after seed + remove `--no-ledger` + readers on authoritative view).

## Out of scope

- Seeding `holding_lots` / removing `--no-ledger` (separate issue).
- WP3 accounting.
- Frontend Settings / glass-box (#1945).
- Exposing private ledger tables.
