## Binding behavior
1. **Fail-soft:** any Mailgun/network error logs a warning and returns — email can never fail or
   delay a pipeline run (test: raising transport ⇒ dispatch returns, run continues).
2. **Dedupe:** one send per `(workspace_id, event_key, date)` via `notification_log` insert-first;
   retry of the whole dispatch is a no-op.
3. **Tier-aware content:** digest builder takes an artifact-class allowlist (import the same
   matrix constants T5 defines; if T5 hasn't merged, define the matrix in
   `digiquant/src/digiquant/notify/entitlements.py` with a comment that T5's `lib/entitlements.ts`
   mirrors it) — an Observer digest contains research/narrative only, never weights/NAV/fills.
4. **Suppression + unsubscribe:** check Mailgun suppression before send (mock in tests); every
   template carries an unsubscribe link (`notification_prefs` toggle URL placeholder).
5. **No PII beyond email:** templates never render broker ids, tokens, fingerprints, or keys —
   golden-file test greps rendered output.
6. Mailgun client: one thin `httpx` (or stdlib) POST wrapper, API key from env, never logged.
