## Binding behavior
1. Client validates with the JSON schemas for instant feedback; the Edge Function re-validates —
   client validation is UX, server validation is the gate.
2. Profile saves are **versioned appends**: new `olympus_profile_config` row with fresh
   `version_id`, `supersedes` pointer if the table carries one; `profile_key` = workspace-scoped
   slug, never `house` (fail closed on the reserved key — mirror `profile_config.py` invariant).
3. Brokers tab renders `fingerprint`, `broker`, `env`, `status`, `last_used_at` ONLY. No secret
   round-trips: after save the plaintext never returns to the client (assert in tests).
4. Alpaca connect: build authorize URL with `env=paper` + `state` (anti-CSRF nonce stored in
   sessionStorage); callback page posts the code to the Edge Function; function exchanges + seals.
   IBKR v1: API-credential entry per K2 IBKR-NOTES (self-service/dev), clearly labeled beta.
5. Optimistic-concurrency on profile saves: send the last-seen version id; function returns 409 on
   mismatch; UI surfaces "profile changed elsewhere — reload".
6. Static export rules hold (client components, `NEXT_PUBLIC_*` only in the bundle).
