## Binding behavior (from spec §7 — implement exactly)
1. **Read path never opens a brokerage session.** `get_account`/`get_positions` ride the
   SSO/live-session layer (`/portfolio/accounts` → `/portfolio/{id}/positions/{page}` paginated,
   `/portfolio/{id}/summary`). Test asserts the mock transport never saw `ssodh/init` on reads.
2. Session lifecycle explicit: `connect()` = auth status + live-session establishment;
   `keepalive()` exposed (`POST /tickle`); **no threads inside the adapter** — the caller owns the
   tickle loop. Expired session → one transparent re-auth attempt, then `BrokerAuthError`.
3. Order path (flag `DIGIQUANT_IBKR_ORDERS=1` only): brokerage session init with
   `compete=false`; a "competing session" response surfaces as status, never kicks the user;
   conid resolution via `/iserver/secdef/search` (cache per symbol); submit
   `POST /iserver/account/{id}/orders`; handle the **reply/confirmation chain**
   (`POST /iserver/reply/{id}`) against a hard-coded allowlist of suppressible message ids —
   any question off the allowlist aborts with `BrokerOrderRejected(question_text)`. Re-apply the
   suppression list after every session init.
4. Pacing: ≥5s spacing on `/portfolio/accounts`, `/iserver/orders`, `/iserver/trades` (simple
   monotonic-clock guard in the adapter); global budget documented as 10 req/s.
5. Decimal discipline and no-secret logging as in K1 (share exception classes from `contracts.py`).
