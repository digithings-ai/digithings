## Binding behavior (implement exactly)
1. AES-256-GCM; fresh random 96-bit nonce per seal; AAD = `f"{workspace_id}:{broker}:{env}"` so a
   row's ciphertext cannot be replayed onto another connection row; `key_id` column names the
   master-key version (rotation = new key env var + re-seal job later, out of scope).
2. Master key from `DIGIQUANT_VAULT_MASTER_KEY` (base64, exactly 32 bytes after decode) — fail
   closed at first use with a clear error; never a default key; never logged.
3. Plaintext payloads are canonical JSON: `{"kind":"oauth","access_token":…}` or
   `{"kind":"api_key","key_id":…,"secret":…}` — validated by Pydantic models before seal.
4. `fingerprint` = first 8 hex of sha256(plaintext secret material) — display-safe, stored, and
   the ONLY thing any API/log ever shows. A test captures logging around seal/unseal and asserts
   the plaintext never appears in any record (repr, exception message, log).
5. Unseal returns a context-manager or short-lived object; callers must not persist plaintext.
   Revoked/expired rows fail closed on unseal (`ConnectionRevokedError`).
6. Test vectors: generate once, commit; the future Edge Function TS implementation must pass the
   same `vectors.json` (note this contract in the file header).
