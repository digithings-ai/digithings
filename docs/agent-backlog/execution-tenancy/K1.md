## Binding behavior (from spec §6 — implement exactly)
1. `AlpacaAdapter(auth: ApiKeyAuth | OAuthAuth, env: Literal["paper"] = "paper")`. SDK client:
   `TradingClient(api_key=…, secret_key=…)` or `TradingClient(oauth_token=…)`, always `paper=True`.
   Constructing with anything but paper raises `LiveVenueNotAuthorizedError` (no env override
   exists in this WP — the flag check lands with the live epic, not now).
2. Idempotency: every submit sets Alpaca `client_order_id = req.client_order_id`; on transport
   failure, call `get_order_by_client_id` before any retry (the fill may have landed).
3. Local validation before submit: `notional` set or fractional `quantity` ⇒
   `time_in_force == DAY` else raise `BrokerOrderRejected("fractional/notional requires day TIF")`;
   `extended_hours` is never sent (v1 off).
4. Error mapping: 401/403 → `BrokerAuthError`; 422 → `BrokerOrderRejected(message, code)`;
   429 → `BrokerRateLimited(retry_after)` honoring `X-RateLimit-*` when present, bounded
   exponential backoff (max 3 tries, jitter); anything else → `BrokerTransportError`. Define these
   exceptions in `alpaca.py` or promote to `contracts.py` if K2 will share (prefer contracts).
5. Decimal discipline: parse Alpaca string decimals via `Decimal(value)`; never float.
6. Mapping tables: our `BrokerOrderRequest` → `MarketOrderRequest`/`LimitOrderRequest`;
   Alpaca `Order.status` → `BrokerOrderStatus` (map unknown → `submitted` + warn log);
   fills come from closed-order `filled_qty/filled_avg_price` or activities — document choice.
7. Logging: never log token/secret; log a 6-char fingerprint (sha256 prefix) + `X-Request-ID`.
