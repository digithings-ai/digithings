## Binding behavior (implement exactly)
1. `resolve_venue(workspace_id: UUID | None) -> ExecutionVenue` in `policy.py`: house/system
   (`workspace_id is None`) → `PAPER_INTERNAL`, **hard-coded, not configurable**; workspace →
   stored execution policy (default `PAPER_INTERNAL`); any `*_LIVE` value → raise
   `LiveVenueNotAuthorizedError` (test-pinned invariant).
2. Kill switch `OLYMPUS_KAIROS_ROUTING` (default off/absent): off ⇒ only `PAPER_INTERNAL`
   reachable regardless of policy (mirror the `OLYMPUS_PORTFOLIO_LEDGER` pattern in `ledger_io`).
3. External submit: build `BrokerOrderRequest` from the pending `OrderIntent`
   (`client_order_id = str(order_intent_id)`; side from `DecisionIntent.action` — TRIM/EXIT sell,
   ADD buy; NO_OP/REJECT with a pending intent = inconsistent chain ⇒ refuse, don't guess);
   append one `broker_orders` row with deterministic id `uuid5(ns, f"{order_intent_id}:{broker}:{date}")`.
   Retry after crash recomputes the same id and collides — never duplicates.
4. Sync job (`sync.py`, callable from cron): per active connection, pull order status + fills
   since a stored cursor → append status rows (backward `supersedes_id` chain, same convention as
   `portfolio_ledger_order_intents`) + `broker_executions` (id = `uuid5(connection_id, external_fill_id)`,
   UNIQUE-backed); daily account/positions snapshot row. REST polling only; budgets: Alpaca ≤6
   calls/connection/cycle, IBKR ≥5s between paced endpoints (use adapter's pacing guard).
5. Reconciliation: when snapshot positions disagree with our mirrored expectation, append a
   report row / structured log + surface flag — **never** auto-submit corrective orders.
6. All writes append-only; `upsert` must not appear in this WP (same rule as `execution_io`).
