## Goal

The accumulation/distribution curve is currently **21 independently-settable nodes**. That is the
right *runtime* representation — `AccumDistCurve` stays exactly as it is — but it is the wrong
*authoring and optimization* surface:

- 21 free parameters is not a search space an optimizer can cover honestly; it is a space in which
  anything can be overfitted to any history.
- Nothing structurally enforces the behaviour the strategy is actually supposed to have. A hand-typed
  node list can be non-monotonic, can buy at high risk, can sell at low risk, and can have no flat
  region at all — all of which pass `AccumDistCurve.__init__`, which validates only node count and
  finiteness.

The owner's requirement is a **shape**: flat around fair value, progressively harder to buy as
valuation falls, progressively harder to sell as it rises. Encode the shape, expose its parameters,
and generate the 21 nodes from them.

## Design

New `sdca/curve_shape.py` — a frozen Pydantic v2 model that **generates** `curve_nodes`:

| Param | Meaning |
|---|---|
| `buy_max_rate` | daily % of *cash* deployed at risk 0 (max fear) |
| `buy_knee_risk` | risk at which buying reaches zero — the lower edge of the dead zone |
| `sell_knee_risk` | risk at which selling starts — the upper edge of the dead zone |
| `sell_max_rate` | daily % of *holdings* sold at risk 100 (max greed) |
| `buy_curvature` | ≥1; 1 = linear ramp, >1 = back-loaded (accelerates only near the extreme) |
| `sell_curvature` | same, for the distribution side |

`to_nodes() -> tuple[float, ...]` evaluates the shape at risk 0, 5, …, 100 and returns the 21 nodes
`AccumDistCurve` already consumes. So the runtime path, the parity harness, and `SdcaStrategy` are
all untouched — this is a generator in front of an unchanged consumer.

Invariants the model must enforce at construction, because they are the strategy's actual thesis:

- `buy_knee_risk < sell_knee_risk` — the dead zone is non-empty, so around fair value the strategy
  genuinely does nothing.
- Nodes are `> 0` strictly below `buy_knee_risk`, exactly `0` across the dead zone, `< 0` strictly
  above `sell_knee_risk`. Never buy when rich; never sell when cheap.
- The buy side is monotonically non-increasing in risk and the sell side monotonically non-increasing
  too — "progressively more as it gets cheaper" is a *monotonicity* claim and should be impossible to
  violate by construction.
- `sell_max_rate <= 100` — you cannot sell more than you hold. (`size_trade()` clamps this at runtime
  too, but a config that *intends* to oversell is a config bug worth rejecting at construction. Note
  #2552 left the "should `AccumDistCurve` bound node magnitude?" question open; answer it here for
  the generated path at minimum, and say in the PR body whether you also bounded the raw
  constructor.)

`long_only` stays where it is — a clamp on the strategy config, not a second shape.

## Scope

1. `sdca/curve_shape.py` with the model, `to_nodes()`, and the invariants above.
2. Re-express the four existing `presets.json` personalities as shape parameters, keeping
   `presets.py`'s public API (`list_presets()`/`load_preset()`) unchanged. Where a hand-authored
   preset cannot be reproduced exactly by the shape, **say so in the PR body with the node-by-node
   diff** rather than silently changing a published personality — and check whether the difference is
   the shape being wrong or the hand-authored curve having been arbitrary.
3. A property test over the parameter space: for any valid parameter set, the generated nodes
   satisfy every invariant.

## Acceptance criteria

- [ ] `SdcaCurveShape(...).to_nodes()` returns 21 nodes accepted by `AccumDistCurve`.
- [ ] Construction raises on an empty/inverted dead zone, on a sell rate above 100, and on parameters
      that would produce a non-monotonic side.
- [ ] Property test (hypothesis or a parameter sweep) asserts sign, monotonicity, and dead-zone
      invariants across the space.
- [ ] All four presets load and produce valid curves; any deviation from the previous nodes is
      documented in the PR body.
- [ ] `AccumDistCurve`, `run_backtest()`, and `SdcaStrategy` are unchanged.
- [ ] `pytest -m unit -k sdca` passes; `make score` clears all four dimensions.
