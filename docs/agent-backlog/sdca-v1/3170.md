## Goal

Make `python digiquant/scripts/generate_tearsheets.py --strategy btc_sdca` work. Today it cannot, and
the reasons are structural rather than incidental — the whole publish path was built around one
strategy family.

## What blocks it today

1. **`generate_tearsheets.py::run_nautilus()` builds every strategy through `get_strategy()`**, and
   SDCA is deliberately absent from `strategies/registry.py` because `risk_path` can only be known at
   runtime. `m2_liquidity` has the identical problem and made the identical choice, so this is a
   **second instance of one pattern** — solve it as a pattern, not with an `if strategy ==
   "btc_sdca"` branch.
2. **`settings.json` describes only the Slapper family** — `symbol`/`ccxt_symbol`/`label`/`kind`,
   with structural defaults assuming one shared shape. There is no field saying *which strategy
   class* an entry drives.
3. **`resolve_calibrations()` is Slapper-shaped.** SDCA has no private indicator calibrations; it has
   a public curve and a coefficients file. It must not be forced through the calibrations gate (nor
   silently pass a `--allow-example-calibrations` check that means nothing for it).
4. **`run_nautilus()` passes `trade_size=Decimal(1)`** into every config. `SdcaStrategyConfig` has no
   `trade_size` and is a frozen msgspec struct — this raises.
5. `_PUBLISHED_BASELINE` drift-warning and `trades_from_positions()` both assume round-trip
   long/short positions.

## Scope

1. **A strategy-type field in `settings.json`** (`"strategy_type": "slapper" | "sdca"`, defaulting to
   `slapper` so existing entries are untouched), plus an `sdca` block per entry carrying `preset` (or
   shape params, once #3169 lands), `risk_model`, `long_only`, and `initial_cash`.
2. **A pre-backtest materialization hook.** For `strategy_type == "sdca"`, `run_and_write()` calls
   `build_risk_index()` (#3168) on the same OHLCV frame it is about to backtest and writes the
   parquet to a temp path, which is then passed as `risk_path`. Critically: **build the index from
   the already-`apply_signal_delay()`-truncated frame**, not the full cache — otherwise the risk index
   leaks bars from beyond the published window and the #1462 signal-delay guarantee is quietly
   broken. Add a test that pins this.
3. **Register SDCA** with a `risk_path`-less `default_params`, injected via the existing
   `**overrides` path, and stop `run_nautilus()` from passing `trade_size` to configs that do not
   declare it (inspect the config class rather than special-casing a name — this fixes `m2_liquidity`
   too).
4. **Skip the calibrations gate for non-Slapper families** and record the actual provenance instead:
   which coefficients file and which preset/shape produced the run.
5. `settings.json` entry for `btc_sdca`: `symbol: BTC-USD`, `label: "BTC Strategic DCA"`, `kind:
   "dca"` (the frontend taxonomy already has `dca`).

## Acceptance criteria

- [ ] `generate_tearsheets.py --strategy btc_sdca` completes and writes a tearsheet JSON.
- [ ] The Slapper runs are byte-identical to before this change (regenerate all three and diff — a
      publish-path refactor that moves a published number is a regression).
- [ ] A test asserts the SDCA risk index is built from the signal-delayed frame: with
      `--signal-delay-days N`, no risk-index row exists after the truncated end date.
- [ ] `trade_size` is only passed to configs that declare it, verified by a test that builds both a
      Slapper and an SDCA config.
- [ ] Running `btc_sdca` without `calibrations.json` present succeeds and does not print a
      calibrations warning.
- [ ] The tearsheet notes record the coefficients file, its fit window, and the preset/shape used.
- [ ] `pytest -m unit -k "tearsheet or sdca"` passes; nautilus smoke covers one SDCA run; `make score`
      clears all four dimensions.
