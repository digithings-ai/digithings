## Goal

Close the integration gap the #3160 review found: **`BtcPowerLawRiskModel` is unreachable from
`SdcaStrategy`.** Every piece exists — rails, valuation-z, composite risk, and a strategy that loads a
`date`/`risk` parquet — but nothing joins them, so today the only way to run SDCA on real rails is to
hand-assemble the parquet in a notebook.

This is pure wiring. No new maths, no new indicators.

## Scope

### 1. `digiquant/src/digiquant/strategies/sdca/risk_index.py`

```python
def build_risk_index(
    dates: pl.Series,
    price: pl.Series,
    risk_model: RiskModel,
    extra_indicators: list[IndicatorWeight] | None = None,
    valuation_weight: float = 1.0,
) -> pl.DataFrame:  # columns: date, risk (+ diagnostics)
```

Pipeline, all of it already-written functions:

1. `risk_model.rails(dates)` → `low`/`median`/`high`
2. `valuation_z_score(price, low, median, high)` → the primary indicator's z
3. wrap as `IndicatorWeight(name="valuation", z=..., weight=valuation_weight)`, concatenate
   `extra_indicators`
4. `compute_composite_risk([...])` → `composite_z`, `risk`
5. return `date`, `risk`, plus diagnostic columns (`price`, `low`, `median`, `high`, `valuation_z`,
   `composite_z`) — the diagnostics are what make a published tearsheet auditable and are what
   #3172 will chart.

Null semantics are already settled upstream and must not be re-invented here: a null in any *enabled*
indicator makes that day's `risk` null, and `SdcaStrategy.on_bar()` treats null risk as an explicit
no-trade day. Just let it flow through.

### 2. `write_risk_index(df, path)`

Writes the two-column parquet `SdcaStrategy` expects. It must satisfy every validation
`_load_risk_index()` already enforces (`date` is `pl.Date`, `risk` numeric, no null dates, no
duplicate dates, no non-finite risk) — so **add a test that round-trips `write_risk_index()` through
`SdcaStrategy._load_risk_index()`**, which is the only way to keep the writer and the reader from
drifting apart.

### 3. MCP tool `digiquant_build_sdca_risk_index`

Platform-level, same shape as `digiquant_fit_btc_power_law` (#1082): reuse
`data/prices/history_cache.py` for prices (`incremental_update`/`load_cached`, never a bespoke
fetch), load the risk model, write the parquet, return JSON with the output path, row count, date
span, and the null-risk day count.

Arguments: `ticker`, `cache_dir`, `refresh`, `risk_model` (`"btc_power_law"` for now — a string
selector, so #3175 can add providers without changing the signature), `coefficients_path`,
`output_path`.

      `build_risk_index()` → parquet → `SdcaStrategy` in a Nautilus backtest that submits at least one

      rather than raising on a missing cache / missing coefficients.
