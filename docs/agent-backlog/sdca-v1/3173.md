## Goal

`sdca/btc_power_law.py` is real, tested code fitting real quantile regressions — but the only
coefficients in the repo are `btc_power_law_coefficients.example.json`, **fitted to a synthetic
fixture**. `load_coefficients()` falls back to it with a warning. Every rail, every valuation
z-score, and therefore every risk score computed today is derived from made-up data.

Publishing a tearsheet on those rails would be a fabricated public number. This issue produces the
real fit.

## Scope

1. **Fill the cache** — `digiquant_fetch_coinbase_ohlcv` / `incremental_update("BTC-USD",
   bulk_period="max")`. Record the actual first and last bar dates.
2. **Run the fit** — `digiquant_fit_btc_power_law` (already shipped). Persist to
   `btc_power_law_coefficients.json`.
3. **Validate the rails before trusting them.** The fit code guards convergence and history length
   (#3160), but a converged fit can still be a bad model. Check and report:
   - coverage — roughly q% of history below each `q` rail, per rail;
   - non-crossing after rearrangement, over the full fit window *and* extrapolated forward 5 years;
   - stability — refit on history truncated to 2020 and to 2023; if the rails move enough to change
     the risk band on a large share of days, the model is fragile and that is a finding, not a
     footnote;
   - sanity — where does today's price sit? A model putting the present at the 1st or 99th
     percentile is telling you something is wrong.
4. **Resolve the `low`/`high` default.** `BtcPowerLawRiskModel` defaults to `q10`/`q95` — asymmetric,
   and chosen without validation because the reference artifact was unreachable. Either justify the
   asymmetry from the coverage data or change it, and say which in the PR body.
5. **Decide whether the coefficients file is committed.** It is currently git-ignored, with the
   placeholder checked in. A published strategy needs reproducible rails, so the real coefficients
   almost certainly should be checked in (they are a fitted public model, not a private calibration —
   unlike `calibrations.json`). Make the call explicitly and record the reasoning; if committed, the
   fit window and data source must be in the file and in the tearsheet notes.

## Acceptance criteria

- [ ] Real coefficients produced from real BTC daily history; fit window and row count recorded.
- [ ] Coverage, non-crossing, stability, and present-day-percentile results reported in the PR body
      with numbers.
- [ ] The `q10`/`q95` default is either justified with data or changed.
- [ ] Committed-vs-ignored decision made explicitly, with reasoning.
- [ ] `load_coefficients()` no longer emits the placeholder warning in the normal path; the fallback
      and its warning remain for a fresh checkout.
- [ ] `pytest -m unit -k sdca` passes — the synthetic fixtures stay as unit fixtures; do not make unit
      tests depend on the network or on committed real coefficients.
